Stage 01 · Preparation

Python Foundations

Two months of Python, aimed at one target: the next stage, where you work with data and AI. So you do not only learn to write programs here — you learn to think in whole collections, to clean data that arrives broken, and to group and chart it with nothing but Python. By hand, on purpose. When NumPy and Pandas arrive in Engineering Fundamentals, they land as the answer to problems you have already felt.

  1. 1

    Weeks 1–2

    Input, output, numbers

    You learn

    • input(), print(), f-strings
    • int, float, str, bool and casting
    • Arithmetic, //, %, rounding, precedence
    • Strings: indexing, slicing, .upper(), .split(), .strip()
    • Conditionals: if / elif / else, and / or / not
    • while loops and len()
    • Your first lists, and asking a whole list a question at once: sum(), max(), len()
    You build

    A *880# / Click UZ clone

    A terminal USSD menu: check balance, transfer money, pay for mobile and utilities. Menu navigation, input validation, and a running balance — all with the basics you just learned.

  2. 2

    Weeks 3–4

    Loops, structures, real data

    You learn

    • for, range(), break, continue, enumerate(), zip()
    • Lists (arrays): append, pop, sort, slicing [1:3]
    • Dictionaries, tuples, sets — and when each one fits
    • Nested lists and dicts — the shape of real JSON
    • List and dict comprehensions
    • Whole-collection thinking: sum(), min(), max(), sorted(key=...), map, filter — one operation over a column, not a loop over rows
    • Counter and defaultdict — counting and grouping without writing the bookkeeping yourself
    • Functions, arguments, defaults, return values
    • Reading a REST API with requests; parsing JSON
    • Reading a CSV file with the csv module
    • Virtual environments, pip, requirements.txt — so you know what pip install actually did
    You build
    • Currency converter — live USD, EUR, RUB rates from the Central Bank API
    • Weather check — today’s weather for any city, from one API call
    • Your first dataset — a real CSV of a thousand rows. Which category appears most? What is the average per city? Which ten rows are the largest? You answer it with Counter, sorted and a comprehension — the same questions, and the same shape of answer, that a data analyst gives every day
  3. 3

    Weeks 5–6

    Storing, cleaning, grouping

    You learn

    • Files: with open(), reading and writing CSV and JSON
    • SQLite: tables, INSERT, SELECT, WHERE, JOIN, GROUP BY
    • An ORM, so rows become Python objects
    • Dirty data: missing values, "Tashkent" vs "toshkent", numbers stored as text, duplicate rows — and how to clean each one
    • Grouping by hand: rows → groups by key → a number per group. The same answer as SQL GROUP BY, written in Python so you see the machinery
    • Joining two lists on a shared key — what a JOIN does outside the database
    • Averages that lie: mean vs median, and when each one misleads you
    • Google Sheets API as a shared, visible database
    • Apps Script to automate the sheet side
    • try / except — not only to survive a crash, but to skip one broken record and still finish the report
    • assert — catching the silent wrong answer, which is worse than a crash
    You build
    • Expense analyser — not just storing spending, but reporting on it: total by category, by month, biggest week. You compute each answer twice, once with SQL GROUP BY and once in plain Python, and the two must match
    • Data cleaner — we hand you a deliberately broken file: blank cells, three spellings of one city, prices as text. You turn it into something you can actually count
    • Attendance sheet — Apps Script fills the sheet, Python reads it back and reports who is falling behind
    • Contact book — add, search and delete contacts in a real database
  4. 4

    Weeks 7–8

    Putting it together

    You learn

    • Classes, objects, methods — structuring a bigger program
    • Modules and your own reusable code
    • .env files — keeping API keys out of your code
    • Git: commits, branches, pushing to GitHub
    • Lists of lists are matrices: [[1, 2], [3, 4]] — rows, columns, and summing along one direction or the other. The idea every array library is built on
    • Percentages, growth, spread — writing standard deviation yourself, once, so the formula stops being a symbol
    • matplotlib: line, bar and scatter charts; axis labels and titles that make a chart readable
    • Jupyter notebooks — working cell by cell, and why analysis lives here while applications live in .py files
    • Reading tracebacks and debugging on your own
    You build
    • Telegram bot — answers from your own database
    • A notebook that answers a question — pick your own dataset, pull it in, clean it, group it, chart it, and write what you found underneath. The whole PRE course in one file, and the exact form of work the next stage runs on
    • Pushing to GitHub — every project committed and published
